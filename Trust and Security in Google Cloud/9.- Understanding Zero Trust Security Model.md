# 🛡️ Understanding Zero Trust Security Model (Comprendiendo el Modelo de Seguridad de Confianza Cero)

El **Zero Trust Security Model** (Modelo de Seguridad de Confianza Cero) es un marco de seguridad moderno que se basa en el principio de **"Never Trust, Always Verify"** (Nunca Confíes, Siempre Verifica). Esto contrasta con los modelos de seguridad tradicionales, que se han demostrado insuficientes en entornos de **Cloud** (Nube) y **Hybrid** (Híbridos).

## 🏢 Modelo de Seguridad Tradicional (Perímetro)

| Característica | Descripción |
| :--- | :--- |
| **Enfoque** | Seguridad aplicada en el **Network Perimeter** (Perímetro de la Red) (ej. un **Corporate Data Center** - Centro de Datos Corporativo protegido por un **VPN** o **VPC**). |
| **Supuesto** | Se asume que **Everything Inside is Trustworthy** (Todo lo que está dentro es de Confianza). Una vez que un recurso está dentro de la red, puede acceder libremente a otros recursos. |
| **Falla** | Si un atacante (**Attacker**) logra penetrar el perímetro (**Perimeter**), puede moverse lateralmente (**Lateral Movement**) sin restricciones dentro de la red. |

## 🚫 Modelo de Zero Trust (Confianza Cero)

El modelo **Zero Trust** establece que **No person or device should be trusted by default** (Ninguna persona o dispositivo debe ser de fiar por defecto), incluso si ya se encuentran dentro de la **Organizational Network** (Red Organizacional).

* **Enfoque:** La **Strict Authentication** (Autenticación Estricta) y **Authorization** (Autorización) de identidad se aplican en **toda la red**, sin importar la ubicación física o lógica del recurso.
* **Beneficio:** Los recursos permanecen seguros incluso si los **Attackers** (Atacantes) logran acceder a la red, ya que necesitarán autenticación adicional para cada recurso al que intenten acceder.
* **Relevancia:** Es esencial en entornos modernos de **Multi-Cloud** (Múltiples Nubes) y **Hybrid Cloud** (Nube Híbrida), donde no existe un único perímetro.

## 🔑 3 Principios Clave de Zero Trust

El modelo de **Zero Trust** se basa en tres principios rectores:

1.  **Assume All Network Traffic is a Threat (Asumir que Todo el Tráfico de Red es una Amenaza):**
    * Tratar todo el **Network Traffic** (Tráfico de Red), incluso el **Internal Traffic** (Tráfico Interno) entre recursos, como una posible amenaza en todo momento.

2.  **Enforce Least Privilege Access (Imponer el Acceso de Menos Privilegio):**
    * Los usuarios y servicios solo deben tener acceso a los recursos que son **absolutely necessary** (absolutamente necesarios) para su función.
    * *Ejemplo:* Si solo se necesita acceso de lectura (**Read Access**) a una base de datos específica, se debe denegar el acceso de escritura (**Write Access**).

3.  **Always Monitor (Vigilar Siempre):**
    * **Continuously Monitor** (Supervisar Continuamente) los recursos y la comunicación entre ellos para detectar y responder a actividades sospechosas de manera inmediata.
