# 📨 Exploring Cloud Pub/Sub - Publishing and Consuming a Message (Explorando Cloud Pub/Sub - Publicando y Consumiendo un Mensaje)

Para lograr la comunicación asíncrona, **Cloud Pub/Sub** sigue un flujo de trabajo de tres pasos principales: creación de recursos, publicación y consumo.

## 🛠️ Creación de Recursos

1.  **Crear un Topic (Tema):** Este es el canal central al que los **Publishers** (Editores) envían sus mensajes.
2.  **Crear Subscriptions (Suscripciones):** Los **Subscribers** (Suscriptores) se registran en el **Topic** creando una suscripción.

### 💡 Conceptos Clave de Suscripción

* **Entrega Discreta:** Cada **Subscription** (Suscripción) representa un **conjunto discreto de mensajes** (*discrete set of messages*) de un **Topic**. Si hay $N$ mensajes en el **Topic** y $M$ suscripciones, los $N$ mensajes se enviarán a cada una de las $M$ suscripciones.
* **Entrega a Clientes:**
    * **Múltiples Suscripciones Diferentes:** Si varios **Subscribers** (Suscriptores) crean sus **propias suscripciones** (*own subscriptions*), **cada uno recibirá todos los mensajes** del **Topic**.
    * **Múltiples Clientes en la Misma Suscripción:** Si varios clientes de aplicación están **vinculados a la misma suscripción**, los mensajes se **dividirán** (*will be split*) entre ellos para el procesamiento paralelo y el escalado de la carga de trabajo.

## 🚀 Envío y Recepción de Mensajes

Una vez que el **Topic** y las **Subscriptions** están listas, el flujo de mensajes es el siguiente:

1.  **Publishing the Message (Publicar el Mensaje):** El **Publisher** (Editor) envía un mensaje al **Topic**.
2.  **Individual Delivery (Entrega Individual):** **Cloud Pub/Sub** entrega el mensaje individualmente a **todas y cada una** (*to all and every single*) de las suscripciones asociadas al **Topic**.

    > **Nota:** **Cloud Pub/Sub** mantiene **colas de mensajes individuales** (*individual message queues*) para cada suscripción.

3.  **Receiving the Message (Recepción del Mensaje):** Los **Subscribers** (Suscriptores) pueden recibir el mensaje mediante dos métodos:
    * **Push:** **Cloud Pub/Sub** envía automáticamente el mensaje al **Webhook Endpoint** (Punto Final de Webhook) del suscriptor.
    * **Pull:** El suscriptor hace una solicitud de **Pull** (Extracción) al **Topic** cuando está listo para procesar mensajes.

4.  **Acknowledging the Message (Reconocer el Mensaje):** Una vez que un suscriptor ha **procesado el mensaje correctamente**, debe enviar un **Acknowledgement (ACK)** (Acuse de Recibo) a **Cloud Pub/Sub**.

    * **Consecuencia del ACK:** El mensaje **solo se eliminará** (*will only be removed*) de la **cola de esa suscripción específica** cuando se reciba el **ACK** de esa suscripción. Esto asegura que el mensaje sea procesado por todos los suscriptores requeridos.
