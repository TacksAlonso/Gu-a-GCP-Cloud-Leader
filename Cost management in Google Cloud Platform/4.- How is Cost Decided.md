# 💰 How is Cost Decided (Cómo se Decide el Costo)

El costo de utilizar los **Google Cloud Services** (Servicios de Google Cloud) se determina mediante la interacción de varios factores clave, desde la configuración del recurso hasta la ubicación y la transferencia de datos.

---

## 1. ⚙️ Factores Determinantes del Costo

| Factor | Descripción | Impacto |
| :--- | :--- | :--- |
| **Resource Type and Configuration** (Tipo y Configuración del Recurso) | El tipo de servicio de nube que se utiliza y cómo está dimensionado. | Define el precio base (ej. la cantidad de **CPU** y **Memory** - Memoria solicitadas para una **Virtual Machine (VM)**; el **Access Tier** - Nivel de Acceso utilizado para **Cloud Storage**). |
| **Usage Counters** (Contadores de Uso) | Medidas específicas de cuánto y cómo se consume el servicio. | **VM Uptime** (Tiempo de actividad de la VM), **I/O** (Entrada/Salida) de disco, número de **Cloud Function Invocations** (Invocaciones de funciones en la Nube). |
| **Region** (Región) | La ubicación geográfica donde se despliega el recurso. | **Crucial:** Los precios varían significativamente entre regiones (ej. una **VM** puede costar $48/mes en `us-central1` (Iowa) y $62/mes en Tokio). |
| **Reservation** (Reserva) | Si se ha adquirido un compromiso de uso a largo plazo. | Obtener **Committed Use Discounts (CUDs)** (Descuentos por Uso Comprometido) de 1 o 3 años reduce el costo total en la mayoría de los servicios de **Compute** (Cómputo). |

---

## 2. 🌐 El Costo de Data Transfer (Transferencia de Datos)

La transferencia de datos, o **Networking** (Redes), es un factor de costo complejo y crucial a gestionar:

### A. Data Ingress (Datos de Entrada) vs. Data Egress (Datos de Salida)

| Tipo de Transferencia | Origen/Destino | Costo General |
| :--- | :--- | :--- |
| **Ingress** (Entrada) | Desde el **On-Premises** (Local) o Internet **hacia** Google Cloud. | **Free** (Gratuito). |
| **Egress** (Salida) | **Desde** Google Cloud hacia el **On-Premises** o Internet. | **Charged** (Se cobra). |

### B. Transferencia Dentro de Google Cloud

Es vital diseñar la arquitectura para minimizar el **Egress** (Salida) interno:

* **Comunicación Inter-Región:** Si un **Cloud Service** en una **Region** (Región) se comunica con otro **Cloud Service** en una **Different Region** (Región Diferente), se genera un **Charge** (Cargo).
* **Comunicación Intra-Zone:** Para evitar los costos de transferencia de datos entre servicios de Google Cloud:
    * Asegúrese de que la **Application** (Aplicación) y la **Database** (Base de Datos) estén desplegadas en la **Same Zone** (Misma Zona).
    * Utilice **Internal IP Addresses** (Direcciones IP Internas) para la comunicación.
    * En este escenario, tanto el **Ingress** como el **Egress** entre los servicios son **Free** (Gratuitos).
