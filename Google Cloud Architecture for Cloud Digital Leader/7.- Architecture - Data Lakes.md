# 🏞️ Architecture - Data Lakes (Arquitectura - Lagos de Datos)

El concepto de **Data Lake** (Lago de Datos) surge como respuesta a la complejidad y alto costo de las soluciones tradicionales de **Big Data**. Busca combinar **almacenamiento, gestión y análisis** (*storage, management, and analysis*) en una plataforma flexible y rentable.

## ☁️ Cloud Storage como Base del Data Lake

En Google Cloud, el servicio fundamental y preferido para un **Data Lake** es **Cloud Storage** (Almacenamiento en la Nube).

* **Almacenamiento Desacoplado:** Almacenar datos en **Cloud Storage** permite separar el **Storage** (Almacenamiento) del **Compute** (Cálculo), lo que aporta una gran **Flexibility** (Flexibilidad) y **cost savings** (ahorro de costes).
* **Características:** Ofrece bajo costo, **Eleven Nines Durability** (Once Nueves de Durabilidad) y alto rendimiento.

## 📥 1. Data Ingestion (Ingesta de Datos)

El primer paso es llevar los datos a **Cloud Storage**:

| Tipo de Datos | Servicio de Google Cloud | Propósito |
| :--- | :--- | :--- |
| **Streaming Data** (Datos de Flujo) | **Cloud Pub/Sub** (Publicación/Suscripción en la Nube) + **Cloud Dataflow** (Flujo de Datos) | Ingestión y procesamiento en tiempo real antes de escribir en **Cloud Storage**. |
| **Small Batch Data** (Lotes Pequeños) | **gsutil** | Utilidad de línea de comandos para transferencias sencillas. |
| **Larger Batch Data** (Lotes Mayores) | **Transfer Service** (Servicio de Transferencia) | Servicio en línea para grandes transferencias (ej. de AWS o *on-premises*). |
| **Massive Batch Data** (Lotes Masivos) | **Transfer Appliance** (Dispositivo de Transferencia) | Dispositivo físico para transferencias de **terabytes** o **petabytes** a gran escala. |

## 🧠 2. Processing and Analytics (Procesamiento y Analítica)

Una vez que los datos están en **Cloud Storage**, la ventaja clave es la capacidad de realizar **In-Place Queries** (Consultas *In-Situ*) sin necesidad de mover o duplicar los datos a otro servicio de almacenamiento más caro.

| Herramienta de Google Cloud | Patrón de Uso | Beneficio |
| :--- | :--- | :--- |
| **BigQuery** (Consulta Grande) | **Federated Data Sources** (Fuentes de Datos Federadas) | Permite ejecutar consultas **SQL** directamente sobre los datos en **Cloud Storage** (**In-Place Queries**). |
| **Cloud Dataproc** (Procesamiento de Datos) | Clúster gestionado de **Hadoop/Spark** | Puede ejecutar *jobs* y consultas complejas directamente sobre los datos almacenados en **Cloud Storage**. |
| **Dataprep** (Preparación de Datos) | Limpieza y transformación visual | Se utiliza para limpiar y transformar los datos que residen en **Cloud Storage**. |
| **Cloud Datalab** (Laboratorio de Datos en la Nube) / **Jupyter Notebooks** | **Data Science** (Ciencia de Datos) y exploración interactiva. | Permite usar **Python**, **SQL** y librerías de ciencia de datos (como **TensorFlow** y **NumPy**) para explorar interactivamente los datos en **Cloud Storage**. |

> **Conclusión:** Almacenar datos en **Cloud Storage** como base del **Data Lake** permite construir una **Simple Big Data Solution** (Solución de Big Data Sencilla) donde el cálculo se ajusta de forma flexible a la necesidad de consulta y procesamiento.
