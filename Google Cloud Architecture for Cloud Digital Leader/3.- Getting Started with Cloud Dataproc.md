# ⚙️ Getting Started with Cloud Dataproc (Introducción a Cloud Dataproc)

**Cloud Dataproc** (Procesamiento de Datos en la Nube) es el servicio de Google Cloud para ejecutar cargas de trabajo de **Big Data** utilizando *frameworks* de código abierto como **Apache Spark** y **Apache Hadoop**.

## ☁️ Características y Casos de Uso

* **Servicio Gestionado:** **Cloud Dataproc** proporciona un servicio **Managed** (Gestionado) para ejecutar cargas de trabajo complejas de **Spark** y **Hadoop**.
* **Cargas de Trabajo Típicas:** Se utiliza para **Complex Batch Processing** (Procesamiento por Lotes Complejo), **ML** (*Machine Learning*) y **AI** (Inteligencia Artificial) sobre grandes volúmenes de datos.
* **Ecosistema:** Soporta la mayoría de las herramientas y *frameworks* del ecosistema **Hadoop/Spark** (Spark SQL, Hive, Pig, etc.).
* **Migración:** Es la herramienta ideal para migrar (*lift-and-shift*) clústeres de **Spark** y **Hadoop** existentes desde entornos *on-premises* a **Google Cloud**.

## 💻 Configuración de Clústeres

**Cloud Dataproc** utiliza **Virtual Machines (VMs)** (Máquinas Virtuales) para crear y gestionar los clústeres.

* **Tipos de Clúster:**
    * **Single-Node Cluster** (Clúster de Nodo Único).
    * **Standard Cluster** (Clúster Estándar).
    * **High Availability Cluster (HA)** (Clúster de Alta Disponibilidad): Utiliza tres **Masters** (Nodos Maestros) para asegurar el procesamiento continuo en caso de fallo de un maestro.
* **Opciones de VM:**
    * Se pueden usar **VMs** normales.
    * Para trabajos **tolerantes a fallos** (*fault-tolerant*) y **no urgentes** (*non-urgent*), se recomienda usar **Preemptible VMs** (VMs Preemptivas) para reducir costes.

## 🔄 Alternativas a Cloud Dataproc

La elección de **Cloud Dataproc** depende de la complejidad y la naturaleza de la carga de trabajo:

| Servicio de Google Cloud | Tipo de Carga de Trabajo | Consideración Clave |
| :--- | :--- | :--- |
| **BigQuery** | Consultas **SQL** a escala (**OLAP**). | Si el procesamiento se puede realizar **solo con consultas SQL** sobre grandes volúmenes de datos. No soporta Spark/Hadoop. |
| **Cloud Dataflow** | **Simple Pipelines** (Tuberías Simples) y transformaciones. | Si se requiere un procesamiento **sin servidor** (*serverless*) y **autoescalable**, sin la necesidad de gestionar explícitamente un clúster de **Hadoop/Spark**. |
| **Cloud Dataproc** | Procesamiento por lotes **complejo** (ML/AI). | Si se requiere la **flexibilidad** y el **ecosistema** completo de **Spark/Hadoop** y se está dispuesto a gestionar el clúster (aunque gestionado por Dataproc). |
