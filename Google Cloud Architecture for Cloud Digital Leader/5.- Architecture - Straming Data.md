# ⚡ Architecture - Streaming Data (Arquitectura - Datos de Flujo)

Cuando se trata de **Streaming Data** (Datos de Flujo), que son datos que llegan de forma continua y en tiempo real, Google Cloud tiene una arquitectura de referencia bien definida para su ingesta y procesamiento.

## 🔗 Pipeline de Flujo de Datos Típico

El flujo de procesamiento en tiempo real se basa en la ingesta, el procesamiento y el almacenamiento especializado:

### 1. Ingestión (Ingestion)

* **Cloud Pub/Sub (Publicación/Suscripción en la Nube):** Es la **elección predeterminada** (*default choice*) para la ingesta de mensajes en tiempo real. Actúa como un *buffer* y desacoplador (*decoupler*).

### 2. Procesamiento y Transformación (Processing and Transformation)

* **Cloud Dataflow (Flujo de Datos en la Nube):** El servicio **Serverless** (Sin Servidor) y **Unified** (Unificado) que se utiliza para implementar la lógica de procesamiento (análisis, agregación, filtrado) sobre los datos de **Pub/Sub**.
* **Cloud Functions (Funciones en la Nube):** Para implementar **lógica sencilla** (*simple logic*), se puede configurar una **Cloud Function** para que escuche directamente los mensajes de **Pub/Sub**.

### 3. Almacenamiento de Destino (Destination Storage)

La elección de la base de datos de destino depende del patrón de consulta deseado:

| Servicio de Google Cloud | Propósito de la Consulta | Características |
| :--- | :--- | :--- |
| **Cloud BigTable (Tabla Grande en la Nube)** | **Real-time Analytics** (Análisis en Tiempo Real) y **Time Series Analytics** (Análisis de Series de Tiempo). | Ideal para consultas y análisis rápidos y **predefinidos**. Base de datos **NoSQL** de baja latencia. |
| **BigQuery (Consulta Grande)** | **Ad-Hoc Complex Queries** (Consultas Complejas Ad Hoc) y Análisis profundo. | Ideal cuando las consultas son **muy complejas** y no están predefinidas, aprovechando el poder del **Data Warehouse** (Almacén de Datos). |
