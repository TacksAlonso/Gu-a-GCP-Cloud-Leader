# 📦 Exploring Container Registry and Artifact Registry (Explorando el Registro de Contenedores y el Registro de Artefactos)

Para microservicios y aplicaciones en contenedores, necesitas un lugar seguro y privado para almacenar las **Docker Images** (Imágenes Docker) que se crean durante el ciclo de **Continuous Integration (CI)**. Las dos opciones de Google Cloud son **Container Registry (CR)** y **Artifact Registry (AR)**.

---

## 1. ⚓ Container Registry (Registro de Contenedores)

**Container Registry (CR)** fue la solución inicial de Google Cloud para el almacenamiento de imágenes Docker privadas, similar a **Docker Hub**, pero dentro del proyecto de GCP.

* **Almacenamiento:** Utiliza **GCS Buckets** (Buckets de Cloud Storage) en el *backend* para almacenar las imágenes Docker.
* **Formatos Soportados:** **Solo puede almacenar Container Images** (Imágenes de Contenedores). No soporta otros artefactos como archivos JAR, WAR o paquetes ZIP.
* **Control de Acceso:** Los permisos se otorgan gestionando el acceso a los **GCS Buckets** subyacentes (usando roles de Cloud Storage).
* **URL Ejemplo:** Las URL terminan en **`gcr.io`** (ej. `us.gcr.io/projectid/imagename`).

> **⚠️ Estatus:** **Container Registry es la solución legada.** La opción preferida y recomendada por Google Cloud ahora es **Artifact Registry**.

---

## 2. 🗃️ Artifact Registry (Registro de Artefactos)

**Artifact Registry (AR)** es la evolución de Container Registry y la **opción recomendada** (*recommended option*) para almacenar todos tus artefactos en Google Cloud.

### 🌟 Características Clave

* **Múltiples Formatos:** Soporta una amplia variedad de **Artifact Formats** (Formatos de Artefactos), incluyendo:
    * **Container Images** (Imágenes de Contenedores - Docker).
    * **Lenguaje Packages** (Paquetes de Lenguajes): Maven (Java), NPM (Node.js), Python, etc.
    * **OS Packages** (Paquetes de Sistema Operativo): APT, YUM.
* **Modelo de Repositorio:** Artifact Registry **no hace uso de GCS Buckets** directamente. Debes **crear un repositorio separado** (*create a separate repository*) para cada tipo de artefacto (ej. un repositorio solo para Docker, uno solo para Maven, etc.).
* **Regiones:** Los repositorios pueden ser:
    * **Regional:** Almacenamiento en una **Región Específica** (*Specific Region*).
    * **Multi-regional:** Almacenamiento replicado en múltiples regiones (ej. US-multi-region, EU-multi-region) para alta disponibilidad.
* **URL Ejemplo:** Las URL terminan en **`pkg.dev`** (ej. `us-central1-docker.pkg.dev/projectid/repositoryname`).

### 🔒 Cifrado y Seguridad

* **Cifrado Automático:** Cualquier cosa que almacenes en el repositorio se **encripta automáticamente** (*automatically encrypted*).
* **Opciones de Cifrado:**
    * **Google-managed key** (Clave Gestionada por Google): Sin configuración requerida.
    * **Customer-managed key (CMEK)** (Clave Gestionada por el Cliente): Se utiliza una clave creada en **Cloud Key Management Service (Cloud KMS)** para el cifrado.

### 🔑 Control de Acceso (IAM)

El acceso a Artifact Registry se controla con roles de IAM específicos y granulares:

* **Roles Predifinidos:** El acceso se gestiona mediante **Predefined IAM Roles** (Roles de IAM predefinidos) de Artifact Registry, como:
    * **Artifact Registry Reader** (Lector): Permite leer y extraer (`pull`) artefactos.
    * **Artifact Registry Writer** (Escritor): Permite leer y escribir/cargar (`push`) artefactos.
    * **Artifact Registry Administrator** (Administrador): Permite crear, eliminar y gestionar repositorios, además de tener permisos de lectura y escritura.
* **Permisos a Nivel de Repositorio:** Puedes configurar **permisos específicos del repositorio** (*repository-specific permissions*) para cada repositorio individual que crees.
