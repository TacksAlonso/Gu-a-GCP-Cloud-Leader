# 🚀 Exploring DevOps Practices (Explorando Prácticas de DevOps)

Las prácticas de **Continuous Integration (CI)**, **Continuous Delivery (CD)** y **Continuous Deployment (CD)** buscan automatizar los pasos del *software delivery lifecycle* (ciclo de vida de entrega de software) para lograr **Fast Feedback** (Retroalimentación Rápida).

## 1. 🔄 Continuous Integration (CI - Integración Continua)

* **Propósito:** Automatizar el proceso de **verificar** y **empaquetar** (*package*) el código tan pronto como se realiza una confirmación (*commit*).
* **Pasos:**
    1.  **Version Control** (Control de Versiones): El desarrollador confirma el código fuente.
    2.  **Unit Tests** (Pruebas Unitarias): Se ejecutan inmediatamente para detectar fallos.
    3.  **Integration Tests** (Pruebas de Integración): Se ejecutan para verificar que los componentes funcionan juntos.
    4.  **Packaging** (Empaquetado): Se construye un artefacto de despliegue (ej. un archivo WAR/JAR, una imagen de Docker).
* **Beneficio:** Garantiza que el código en el repositorio (*repository*) esté siempre en un **estado desplegable** (*deployable state*). Si hay un fallo, el desarrollador lo sabe de inmediato (`fast feedback`).

## 2. 🚚 Continuous Delivery (CD - Entrega Continua)

* **Propósito:** Extender CI para asegurar que el software pueda ser **desplegado en cualquier momento** (*deployed at any time*) en un entorno de **Staging** o **Producción**, pero requiere una **aprobación manual** para ir a Producción.
* **Pasos:** Incluye todos los pasos de CI, además de:
    1.  **Deployment** (Despliegue): El artefacto se despliega automáticamente en entornos reales (ej. Desarrollo, Pruebas, QA).
    2.  **Automated Testing** (Pruebas Automatizadas): Se ejecutan pruebas de sistema o de automatización en el entorno desplegado.
    3.  **Manual Approval Gate** (Puerta de Aprobación Manual): El despliegue a Producción requiere una aprobación explícita (ej. del equipo de QA o de Negocio).

## 3. ☁️ Continuous Deployment (CD - Despliegue Continuo)

* **Propósito:** Extender la Entrega Continua automatizando el despliegue **hasta la Producción** (*all the way to Production*), sin intervención humana.
* **Flujo:** Despliegue continuo a Producción, resultando en **múltiples lanzamientos a Producción en un día** (*multiple releases to production in a day*).
* **Uso:** Utilizado por las principales empresas de tecnología (Google, Amazon, Facebook) para entregar valor continuamente a los clientes.

# 🛡️ Prácticas de Seguridad y Calidad en CI/CD

Como parte de los ciclos de CI/CD, es fundamental integrar la seguridad y la calidad (*Security and Quality*) en todas las etapas.

## 1. 🔍 Static Code Analysis (Análisis Estático de Código - SAST)

* **Definición:** Analizar el código fuente **sin ejecutarlo** (*without running it*) para encontrar errores de codificación, incumplimiento de estándares y vulnerabilidades de seguridad.
* **Objetivos:**
    * **Coding Standards** (Estándares de Codificación): Comprobar que el código cumple las mejores prácticas (ej. usando herramientas como Lin o Sonar).
    * **Static Security Checks** (Comprobaciones de Seguridad Estática): Buscar problemas de seguridad en el código fuente (ej. con Veracode o Static Code Analyzer).

## 2. 🛡️ Runtime Checks (Comprobaciones en Tiempo de Ejecución - DAST)

* **Definición:** Ejecutar pruebas de seguridad **después de que la aplicación haya sido desplegada** en un entorno específico.
* **Objetivos:**
    * **Vulnerability Scanners** (Escáneres de Vulnerabilidad): Encontrar fallos de seguridad en las aplicaciones en ejecución (ej. Inyección SQL, Cross-Site Scripting).
    * **Pruebas de URL/Endpoints:** Verificar que las URL y los puntos finales funcionan correctamente.

## 3. 🧪 Tipos de Pruebas

Las pruebas garantizan la calidad del software a diferentes niveles de granularidad:

| Tipo de Prueba | Nivel de Cobertura | Herramientas Comunes | Propósito |
| :--- | :--- | :--- | :--- |
| **Unit Tests** (Pruebas Unitarias) | Nivel **Micro** (método o clase). | JUnit, Pytest, Jasmine. | Verificar que pequeñas partes de código funcionan correctamente. |
| **Integration Tests** (Pruebas de Integración) | Múltiples componentes que trabajan juntos. | Selenium, Cucumber, Robo Framework. | Comprobar que los módulos se integran sin errores. |
| **System/E2E Tests** (Pruebas de Sistema/Fin a Fin) | La aplicación completa o sistemas integrados. | Selenium, Cucumber, Robo Framework. | Comprobar toda la funcionalidad desde
