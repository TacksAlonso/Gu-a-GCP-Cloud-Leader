# 💻 Exploring DevOps Practices - Infrastructure as Code (Infraestructura como Código)

**Infrastructure as Code (IaC)** (Infraestructura como Código) es una de las prácticas de DevOps más importantes. Consiste en gestionar y aprovisionar la infraestructura de TI **utilizando archivos de configuración legibles por máquina** (*machine-readable configuration files*), en lugar de hardware físico o herramientas de configuración interactivas.

### 📝 Principios Clave de IaC

* **Tratar la Infraestructura como Código:** Crear la infraestructura del mismo modo que se escribe el código de la aplicación.
* **Control de Versiones (`Version Control`):** El código de infraestructura debe almacenarse en un **Version Control System** (Sistema de Control de Versiones - Git), lo que permite:
    * **Tracking Changes** (Seguimiento de Cambios): Monitorear cómo evoluciona la infraestructura a lo largo del tiempo.
    * **Rollback:** Revertir fácilmente a un estado anterior y conocido si hay un problema.
* **Repetibilidad (`Repeatability`):** Ejecutar el mismo *script* o configuración para crear entornos idénticos (ej. Desarrollo, QA y Producción) sin errores manuales.

---

## 🛠️ Componentes de IaC

La IaC se divide en dos fases principales:

## 1. 🏗️ Infrastructure Provisioning (Aprovisionamiento de Infraestructura)

* **Propósito:** Crear la infraestructura básica (redes, cómputo, bases de datos, almacenamiento).
* **Herramientas de Código Abierto (`Open-Source Tools`):**
    * **Terraform:** La herramienta de aprovisionamiento de infraestructura **Cloud-Neutral** (Neutral a la Nube) más popular. Se puede utilizar para aprovisionar infraestructura en **GCP, AWS, Azure**, etc. (Ejemplo: aprovisionar VMs o redes).
* **Servicios Específicos de GCP:**
    * **Google Cloud Deployment Manager (CDM):** El servicio de GCP nativo para el aprovisionamiento de infraestructura. Permite escribir **Deployment Templates** (Plantillas de Despliegue) (utilizando YAML o Python) para crear, configurar y gestionar recursos en GCP. Es muy similar a **CloudFormation** en AWS.

## 2. ⚙️ Configuration Management (Gestión de la Configuración)

* **Propósito:** Una vez que la infraestructura es aprovisionada (ej. una VM), se necesita configurar y mantener su estado. Esto incluye instalar el **software adecuado** (*installing the right software*), herramientas y asegurar que la configuración sea correcta.
* **Herramientas de Código Abierto (`Open-Source Tools`):**
    * **Chef, Puppet, Ansible, SaltStack:** Herramientas populares que automatizan la instalación y configuración de software en miles de instancias de máquinas virtuales, eliminando el trabajo manual.

> **Resumen:** La Infraestructura como Código consiste en **automatizar el aprovisionamiento y la configuración** de la infraestructura, tratando todos los componentes de la nube como código de aplicación.
