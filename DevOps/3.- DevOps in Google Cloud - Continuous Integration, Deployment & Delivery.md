# ⚙️ DevOps in Google Cloud - Continuous Integration, Deployment & Delivery

Google Cloud proporciona un conjunto de herramientas nativas para implementar los flujos de **CI/CD** (Integración/Despliegue/Entrega Continua).

## 🗄️ 1. Source Code Repository (Repositorio de Código Fuente)

* **Servicio:** **Cloud Source Repositories (CSR)** (Repositorios de Código Fuente en la Nube).
* **Función:** Es un **Fully Featured Private Git Repository** (Repositorio Git Privado con todas las funciones).
* **Uso:** Almacenar tu código fuente y configuración, de manera muy similar a cómo se usa GitHub o GitLab, pero de forma privada dentro de GCP.

## 📦 2. Artifact Storage (Almacenamiento de Artefactos)

* **Servicio:** **Container Registry (CR)** (Registro de Contenedores) / **Artifact Registry (AR)** (Registro de Artefactos).
* **Función:** Almacenar tus **Docker Images** (Imágenes Docker) y otros artefactos de despliegue.
* **Nota:** **Artifact Registry** es la evolución y el servicio recomendado de GCP, ya que soporta no solo imágenes de Docker, sino también paquetes Maven, npm y otros.

## 🛠️ 3. Continuous Integration Tooling (Herramientas de Integración Continua)

Las herramientas de CI son responsables de tomar el código fuente y transformarlo en artefactos listos para el despliegue.

* **Cloud Build (Construcción en la Nube):**
    * **Función:** Servicio de **Continuous Integration** (Integración Continua) completamente gestionado (*Managed Service*) por Google Cloud.
    * **Uso:** Se utiliza para **construir artefactos desplegables** (*build deployable artifacts*) a partir del código fuente y la configuración (ej. construir un archivo `.jar`/`.war`, construir una **Docker Image** y enviarla al **Container Registry**).
* **Jenkins:**
    * **Función:** La versión de código abierto (*open-source*) más popular para crear **CI/CD Pipelines** (Tuberías de CI/CD).
    * **Uso:** Puede ser autogestionado en una instancia de **Compute Engine** o **GKE**.

## 🚀 4. Continuous Deployment Tooling (Herramientas de Despliegue Continuo)

Una vez que se construyen los artefactos, el despliegue se encarga de moverlos a los entornos de ejecución.

* **Spinnaker:**
    * **Función:** Una plataforma de **Continuous Delivery** (Entrega Continua) de código abierto diseñada para ejecutar despliegues de **múltiples nubes** (*multi-cloud*).
    * **Beneficios:** Permite lanzar cambios de software con gran **velocidad** (*speed*) y **confianza** (*confidence*).
    * **Destinos:** Puede desplegar en **Google Compute Engine**, **Google Kubernetes Engine (GKE)**, **Google App Engine**, y otras plataformas en la nube.
    * **Estrategias:** Soporta múltiples **Deployment Strategies** (Estrategias de Despliegue), como **Blue/Green** (Azul/Verde), **Canary Deployments** (Despliegues Canarios), entre otras.
