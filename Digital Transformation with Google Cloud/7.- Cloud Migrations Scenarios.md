# Cloud Migrations Scenarios

Al planificar la migración a la nube, se utiliza un marco estratégico para decidir el destino de cada aplicación o sistema heredado (**Legacy System**). Este marco se conoce a menudo como las "6 R's" de la migración.

| Escenario (Scenario) | Estrategia (Strategy) | Definición / Objetivo |
| :--- | :--- | :--- |
| Nuestra empresa tiene una aplicación antigua que ya nadie usa. Nos está costando dinero mantenerla en funcionamiento, por lo que queremos cerrarla. | **Retire (Retirar)** | El sistema no es necesario para el negocio. Se **decomission** (retira) para eliminar costos operativos (**OpEx**). |
| Tenemos un sistema heredado que es crítico para nuestras operaciones diarias, pero aún no es adecuado para la nube debido a problemas de **Compliance** (Cumplimiento Normativo). Lo mantendremos en las instalaciones por ahora. | **Retain (Retener)** | Mantener el sistema en el entorno **on-premises** (local) debido a regulaciones, latencia extrema u otros impedimentos críticos de migración. |
| Queremos mover nuestra aplicación web existente a la nube lo más rápido posible y con la menor cantidad de cambios para beneficiarnos de la **Scalability** (Escalabilidad) y el **Cost Savings** (Ahorro de Costos) de la nube. | **Rehost (Realojar)** (También conocido como **Lift and Shift**) | Mover la aplicación a una **Virtual Machine (VM)** (Máquina Virtual) en la nube (ej. **Compute Engine**) sin realizar cambios en la arquitectura. Es la migración más rápida. |
| Nuestra aplicación es una buena candidata para la nube, pero queremos actualizar su base de datos subyacente a un **Managed Cloud Service** (Servicio de Nube Administrado) para reducir la **Administrative Overhead** (Sobrecarga Administrativa). | **Replatform (Reestructurar la Plataforma)** | Mover la aplicación, pero haciendo **Minimal Modifications** (Modificaciones Mínimas) para aprovechar una característica de la nube (ej. cambiar una base de datos local por **Cloud SQL**). |
| Vemos el potencial de mejoras significativas en nuestra aplicación al adoptar características **Cloud Native** (Nativas de la Nube), por lo que la **Rediseñaremos** para aprovechar al máximo el entorno de la nube. | **Refactor (Refactorizar)** (También conocido como **Rearchitect**) | Reconstruir la aplicación de forma significativa para adoptar **Microservices** (Microservicios) o **Serverless** (Sin Servidor) (ej. migrar a **Cloud Run** o **GKE**). |
| Nuestro sistema actual de gestión de relaciones con los clientes (**CRM**) está obsoleto. Hemos decidido **Cambiar a una solución CRM basada en la nube** en lugar de mover nuestro sistema existente a la nube. | **Repurchase (Recomprar)** (También conocido como **Replace**) | Descartar la aplicación existente y adoptar un **Software as a Service (SaaS)** (Software como Servicio) o un producto comercial de terceros en la nube (ej. migrar de un CRM local a **Salesforce**). |
