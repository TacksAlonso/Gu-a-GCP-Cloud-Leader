# ☁️ Understanding Cloud Native Architectures (Comprendiendo las Arquitecturas Nativas de la Nube)

Las **Cloud Native Architectures** (Arquitecturas Nativas de la Nube) representan un cambio en la forma de diseñar y ejecutar software para aprovechar al máximo el **Cloud Computing** (Computación en la Nube), a diferencia de las arquitecturas heredadas diseñadas para los **Data Centers** (Centros de Datos) tradicionales.

## 📝 Definición de Cloud Native

Aunque no hay una definición única, el objetivo es maximizar el valor de la nube:

* **Google Cloud Definition:** Aplicaciones diseñadas desde cero (**From the Ground Up**) para aprovechar la **Elasticity** (Elasticidad) y la **Distributed Nature** (Naturaleza Distribuida) de la nube.
    * **Elasticity (Elasticidad):** Capacidad de escalar el número de instancias de forma **Dynamically** (Dinámica), aprovisionando y liberando recursos bajo demanda.
    * **Distributed Nature (Naturaleza Distribuida):** Preferencia por arquitecturas que utilizan muchos componentes pequeños y comunicativos (**Microservices**) en lugar de grandes máquinas monolíticas.

## 🎯 Objetivos de Cloud Native

Las arquitecturas **Cloud Native** buscan mejorar tres aspectos clave de la entrega de software:

1.  **Increase Software Delivery Speed (Aumentar la Velocidad de Entrega de Software):** El ritmo al que se crea, prueba y lanza el software a **Production** (Producción).
2.  **Increase Service Reliability (Aumentar la Fiabilidad del Servicio):** Reducir el número de **Production Issues** (Problemas de Producción) y la capacidad de identificarlos y recuperarse rápidamente.
3.  **Increase Collaboration (Incrementar la Colaboración):** Mejorar la sinergia entre los equipos de **Business** (Negocio), **Development** (Desarrollo) y **Operations** (Operaciones).

---

## 🏗️ 4 Pilares de Cloud Native

Las **Cloud Native Architectures** se construyen sobre cuatro pilares tecnológicos y culturales:

### 1. Microservices Architecture (Arquitectura de Microservicios)

* **Enfoque:** Dividir una aplicación monolítica grande en una colección de **Small, Independent Microservices** (Microservicios Pequeños e Independientes) que se comunican entre sí.
* **Beneficio:** Permite a los equipos realizar cambios y solucionar problemas en un servicio sin afectar a los demás, facilitando la **Faster Innovation** (Innovación Más Rápida).

### 2. Containers (Contenedores)

* **Propósito:** Empaquetar el código de la aplicación y todas sus dependencias en una **Container Image** (Imagen de Contenedor) estandarizada.
* **Ventajas:**
    * **Portability (Portabilidad):** La imagen de contenedor se ejecuta de manera consistente en cualquier entorno (**Local Machine**, **Data Center**, **Cloud**).
    * **Lightweight (Ligeros):** Los contenedores se crean y escalan mucho más rápido que las **Virtual Machines (VMs)** (Máquinas Virtuales).

### 3. Container Orchestration (Orquestación de Contenedores)

* **Herramientas:** **Kubernetes** (**Google Kubernetes Engine - GKE** en Google Cloud).
* **Función:** Gestionar y automatizar las complejas necesidades de los **Microservices** en producción:
    * **Auto-Scaling (Autoescalado):** Aumentar o disminuir las instancias basadas en la carga.
    * **Load Balancing (Equilibrio de Carga):** Distribuir el tráfico entre las instancias disponibles.
    * **Self-Healing (Autocuración):** Reemplazar automáticamente las instancias que no funcionan correctamente.
    * **Zero-Downtime Deployment (Despliegue sin Tiempo de Inactividad):** Actualizar el software sin interrumpir el servicio.

### 4. DevOps / Site Reliability Engineering (SRE)

* **Enfoque Cultural:** Promover la colaboración y la automatización entre los equipos de desarrollo y operaciones.
* **Prácticas:** Utilización de **Continuous Integration (CI)** (Integración Continua), **Continuous Deployment (CD)** (Despliegue Continuo) e **Infrastructure as Code (IaC)** (Infraestructura como Código) para automatizar los procesos de creación y despliegue.

---

## ❌ ¿Qué NO es Cloud Native?

* Usar **Virtual Machines (VMs)** para cada servicio.
* Realizar **Manual Deployments** (Despliegues Manuales).
* Crear **Infrastructure Manually** (Infraestructura Manualmente) (sin **IaC**).
